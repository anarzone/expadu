## 0. Ground rules and definition of done

- Match the mock at 360, 390, 768 and 1440 px (also check 1280 and 1512, where the mock was tuned).
- One header per page. No page title row: the `<h1>` stays for screen readers only.
- Dropdowns float over the page. On phones they become sheets where the mock does that (Events pickers).
- 44 px targets. Reduced motion respected.
- Breakpoints: ≤359 small phone, ≤700 phone, 701–999 tablet, ≥1000 desktop, ≥1500 caps width.
- Colours only from token roles: one orange action per section; cyan means selected or travel; lavender means Paperwork; amber means attention; coral means conflict.
- No sample data ships. Everything the mock fakes becomes real data or an honest state: "Not listed", "Recorded 22:19", "Scheduled · not live", "Platform not known".
- No Review menus, scenario switchers, "Sample" chips or preview footers.
- Trips and departures outside Travel reuse Travel's own components.
- No hard-coded legal figures. Paperwork copy, fees and deadlines come only from source-checked card data (`Task::authoritative()`, `RuleSourcePolicy`).

**Definition of done (every UI slice):**

1. Side-by-side screenshots with the mock at 360/390/768/1440 are attached to the ticket.
2. All of these states are reachable and screenshotted: first visit, empty, loading (placeholder only after 140 ms; keep existing content visible), failed (with retry), stale (with its time).
3. A deep link opens the same view on a cold load.
4. Back/Forward restores the view and the scroll position.
5. Keyboard: focus order, Escape, focus returns to where it was.
6. No console errors. No sideways scroll at 320.
7. The old markup, CSS, JS, unused API calls and browser specs this slice replaces are deleted in the same change.
8. `npm run build`, `tsc` and lint are clean.
9. Tests only where the slice touches security or sensitive data (🔒).
